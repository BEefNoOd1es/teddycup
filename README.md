# 泰迪杯数据挖掘挑战赛 - 赛题项目整合与优化报告

## 1. 项目简介

本项目为泰迪杯数据挖掘挑战赛的综合性量化与数据挖掘解决方案。在项目开发过程中，为提升团队协作效率和模型涵盖的广度与深度，项目经历了**单体基础验证阶段（分队前）**到**全链路复合智能处理阶段（分队后）**的重构。

本报告旨在详细说明**分队前后完整的代码结构及内容变动**，明示修改细节，并提供**从零开始一次性跑通全流程**的操作指南。

---

## 2. 目录结构：分队前后的演变

### 分队前（基础版 - 位于 `程序原始版本/` 文件夹）
此阶段主要搭建了量化回测的骨架，功能较为单一，依赖本地预先准备好的数据。
```text
程序原始版本/
├── events_date.json        # [数据] 原始事件日期记录
├── structured_events.db    # [数据] 结构化本地数据库
├── main.py                 # [代码] 早期回测启动入口
├── BacktestEngine.py       # [代码] 基础回测引擎（收益率及净值计算）
├── PortfolioManager.py     # [代码] 仓位及资金管理（基础版）
├── RiskFilter.py           # [代码] 基础风险风控过滤组件
└── MetricsPlotter.py       # [代码] 回测结果基础图表绘制
```

### 分队后（大模型与多维评估整合版 - 位于 `程序/` 文件夹）
针对赛题要求，团队加入网络文本抓取、大语言模型分析、事件研究法及知识图谱等模块。
```text
程序/
├── 【核心数据预处理流水线】
│   ├── cls.py                       # [新增] Playwright 舆情资讯抓取
│   ├── llm_analyze.py               # [新增] DeepSeek/OpenAI API 文本情感与特征解析
│   ├── select_stocks_from_events.py # [新增] 事件与标的资产提取及关联筛选
│   └── main_pipeline.py             # [新增] 自动化数据总控干道（整合上述三步）
├── 【图谱与事件研究】
│   ├── Task2_KnowledgeGraph.py      # [新增] 基于 NetworkX 的实体关联与知识图谱构建
│   └── EventStudy_CAR.py            # [新增] 金融事件研究法异常收益率(CAR/AR)分析
└── 【量化回测与分析引擎】(继承自原始版本并修改)
    ├── main.py                      # [修改] 新的量化调度入口
    ├── BacktestEngine.py            # [修改] 回测引擎
    ├── PortfolioManager.py          # [修改] 高级投资组合管理
    ├── RiskFilter.py                # [修改巨大] 复杂风险模型
    └── MetricsPlotter.py            # [修改] 多维专业可视化
```

## 3. 代码与内容详解 (前后对比及修改说明)

### 3.1 继承并修改的代码内容 (分队前 -> 分队后)
为适配新的大语言模型输出和更严格的比赛要求，分队前留存的代码在逻辑上进行了大量拓展：

1. **`RiskFilter.py`（风险过滤体系）**
   * **分队前原内容**：体积约 26KB，实现了基础的止盈止损、简单的持仓限制。
   * **修改及拓展部分**：代码量暴增至约 43KB。新增了包括“波动率动态惩罚”、“流动性极值剔除”、“市场极端下行熔断机制”等高阶因子。重写了事件触发风险的数据接口，现可对接 `llm_analyze.py` 的负面情绪判定。
2. **`PortfolioManager.py`（投资组合管理）**
   * **分队前原内容**：体积约 5KB，使用简单的等权分配法或均值方差法。
   * **修改及拓展部分**：体积升至约 7KB。加入了考虑到知识图谱上下游传导权重的分配机制，同时优化了换手率限制与滑点冲击成本的扣除。
3. **`main.py`及`BacktestEngine.py`（主程序与回测内核）**
   * **分队前原内容**：读取硬盘固定 `json`，启动基于日期切片的单次回测计算。
   * **修改及拓展部分**：解耦了原有的刚性流程。`main.py` 内部的数据入参被重构，能够平滑接收多因子矩阵。`BacktestEngine` 增加了年化夏普比率、最大回撤持续期等更为详细的高阶指标输出挂载点。
4. **`MetricsPlotter.py`（前端可视化）**
   * **修改部分**：引入了 `seaborn` / `matplotlib` 等专业配色优化，新增关于异常收益率（CAR）的专用分布散点图。

### 3.2 纯新增的代码内容 (分队后为比赛要求扩充)
以下模块为分队后团队为解决赛题痛点专门新增的代码内容：
1. **`cls.py` (资讯获取)**：使用 `playwright` 组件模拟真实游览器访问行为抓取，绕过一般反爬，获取最新赛题指定数据源。
2. **`llm_analyze.py` (大语言模型引入)**：核心突破点，应用 DeepSeek 分析自然语言，自动化抽取 `主体`、`客体`以及`事件情感标签`（利好/利空/中性），并支持断点续跑防止 API 意外断开。
3. **`Task2_KnowledgeGraph.py` (关联挖掘图谱)**：利用 `networkx` 勾勒“产业链/投资情绪”有向图，辅助评估风险蔓延。
4. **`EventStudy_CAR.py` (异常收益测算)**：运用标准金融学范式，针对事件窗[-5, +5]日提取超额收益验证事件真实冲击力度。
5. **`main_pipeline.py` (上游总干道)**：实现上述组件的数据流转与自动装配。

## 4. 如何一次性跑通全项目 (新环境运行指南)

为保证评委及其他合作者能够在本地**无报错、一次性跑通**全部流程，强烈建议基于干净的 `Conda` 环境进行部署。

### 第 1 步：环境隔离与创建
在命令行/终端中运行（需已安装 Anaconda/Miniconda，Python版本推荐 3.9 或 3.10）：
```bash
# 创建独立环境
conda create -n teddy_env python=3.10 -y
# 激活环境
conda activate teddy_env
```

### 第 2 步：安装依赖库与内核
在项目根目录（或新建一个 `requirements.txt` 并写入以下内容）：
```txt
pandas
numpy
matplotlib
networkx
playwright
openai
```
随后执行以下命令安装 Python 库，并配置浏览器内核：
```bash
pip install -r requirements.txt
# 这一步非常重要，用于安装 cls.py 需要的无头浏览器依赖！
playwright install  
```

### 第 3 步：配置 API Key (重要)
在运行前，请打开 `程序/llm_analyze.py` 和可能调用的 API 脚本，在代码内找到 `API_KEY = "你的密钥"` 或者设定系统环境变量，替换为实际的 OpenAI/DeepSeek 鉴权密钥。如无环境生成新事件，这一步可选。

### 第 4 步：顺序执行全流水线
1. **[生成端/非必循] 数据爬取与情绪标注：**
   ```bash
   python 程序/llm_analyze.py
   python 程序/Task2_KnowledgeGraph.py
   ```
2. **[集成干线] 将分析所得数据自动化过滤并组装至回测数据库：**
   ```bash
   python 程序/main_pipeline.py
   ```
3. **[回测终端] 运行核心选股及风控回测以输出可视化：**
   ```bash
   python 程序/main.py
   ```
*运行结束后，程序的表现（累积净值曲线、夏普、最大回撤等）都将在图形界面及终端依次抛出。*
